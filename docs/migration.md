# 旧服迁移与游戏接入

## 导入前

1. 备份旧服务器世界、玩家数据、白名单、权限插件数据库和验证配置。
2. 从旧服实际身份记录导出玩家名称和 UUID，核对 `world/playerdata`、`advancements`、`stats` 以及使用 UUID 的插件数据。
3. 在 MineHub 管理端创建来源服务器，保持服务器标识稳定。
4. 在「站点设置 → 注册与角色」开启旧服迁移。导入完成之前暂停新角色创建。

不能仅根据玩家自报名称生成 UUID。代理、登录插件或历史改名可能使实际存档身份与通常的离线 UUID 算法不同。

## 清单格式

上传 JSON 数组，每条包含 `serverKey`、`name`、`uuid`：

```json
[
  {
    "serverKey": "survival",
    "name": "OldPlayer",
    "uuid": "b50ad385-829d-3141-a216-7e7d7539ba7f"
  }
]
```

这只是格式示例，必须替换成旧服的真实记录。支持带连字符或紧凑的 32 位 UUID；导入不会重新生成身份。文件最多 10 MiB，清单最多 10000 条；错误显示记录位置。相同内容按规范化摘要幂等处理。

在「角色 → 旧服导入」依次选择文件、检查、确认导入。名称和 UUID 冲突阻止整批提交，不覆盖现有归属。同一身份可关联多个来源服务器；同名但 UUID 不同的记录需要先人工处理。

导入完成后核对数量和抽样 UUID，再标记「旧服身份导入完成」以恢复新角色创建。

## 认领

玩家验证邮箱后，在「我的角色 → 认领旧角色」提交来源服务器、旧名称和归属说明。系统不提供完整待认领名单。

管理员需要结合旧账号记录、历史日志、已有联系方式等资料核实身份，不能把知道旧角色名当作归属证明。批准时保留原 UUID，并在事务中绑定用户、关闭竞争申请、写入审计。驳回原因对申请人可见，可以补充资料后重新申请。

认领不会因账户普通角色额度不足而丢弃旧身份。角色改名保留 UUID；软删除与旧名称预留防止身份重新分配。

## 启动器接入

1. 在账户设置的「游戏登录」生成一个命名的游戏专用密码，立即保存。
2. 将账户设置或服务器指南中的「拖入启动器」按钮拖到受支持的启动器窗口，确认添加认证服务器；也可手动添加 `https://你的域名/api/yggdrasil/`。使用网站邮箱和游戏专用密码登录，选择角色。
3. 根据 MineHub 中的服务器入服指南选择版本，再添加服务器地址。

网站密码不用于游戏登录。专用密码撤销后，使用它签发的游戏令牌同时失效。游戏令牌默认 15 天，每账户最多 10 个。改名后需要启动器刷新角色信息。

服务器端按 [authlib-injector 官方接入说明](https://yushijinhun.github.io/authlib-injector/print.html) 加入 JVM 参数：

```sh
java -javaagent:authlib-injector.jar=https://你的域名/api/yggdrasil/ -jar server.jar nogui
```

单机直连服务端使用 `online-mode=true`。代理网络应按对应代理和服务端的身份转发文档配置，不能直接套用单机设置。为现代服务器核对安全档案／聊天签名要求，当前首版没有实现 Mojang 玩家证书签发。
